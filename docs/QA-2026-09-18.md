# QA — δοκιμή χρήστη σε όλη την υποδομή (18/9/2026)

Μέθοδος: αυτόματη διάβαση όλων των οθονών (43 για Full, 21–22 για περιορισμένους) με 4 χρήστες
(pdelis/Full, nkonstantakopoulos/επικεφαλής R&D, jmitrousis/μέλος R&D, efemma/Manager) σε desktop 1500px
και κινητό 390px, χειροκίνητες ροές (καρτέλα εργασίας, παλέτα «Νέο», πελάτες, προσφορές, inbox,
ημερολόγιο, chat, ρυθμίσεις, ομάδες, υπόλοιπα, αναφορές, καμπανάκι), ακραίες τιμές στο API,
έλεγχος δεδομένων/ορφανών, logs, healthcheck. Κάθε εύρημα έχει βαθμό: **Α** = λάθος συμπεριφορά /
απώλεια δεδομένων, **Β** = μπερδεύει τον χρήστη, **Γ** = κοσμητικό / βελτίωση.

## Α — να διορθωθούν πρώτα

| # | Πού | Τι | Πώς αναπαράγεται |
|---|---|---|---|
| A1 | `save_task` | **Καμία επικύρωση ημερομηνιών**: δέχεται Λήξη πριν την Έναρξη και Deadline πριν τη Λήξη (υπάρχει ήδη 1 τέτοια εργασία). | POST save_task start=2026-09-20 due=2026-09-10 → `ok` |
| A2 | `save_task` | **Ανάθεση σε ανύπαρκτο/απενεργοποιημένο admin γίνεται δεκτή** (assignee=99999 αποθηκεύτηκε). Η εργασία «χάνεται» — δεν τη βλέπει κανείς στη Μέρα του. | POST save_task assignee=99999 → `ok` |
| A3 | `save_task` / `time_add` | **Εκτίμηση χωρίς όρια** (999999΄ έγινε δεκτό, αρνητική επίσης) και **καταχώρηση 100.000 λεπτών** χωρίς επιβεβαίωση. Ένα λάθος πληκτρολόγησης γίνεται 1.666 ώρες χρέωσης. | time_add mins=100000 → `ok` |
| A4 | `task_delete` | **Μένουν ορφανά**: τα συνημμένα ενεργειών (`mod_cpm_storage` ref_type=check) και οι αντιδράσεις (`mod_cpm_check_react`) δεν σβήνονται με την εργασία — ήδη 6 ορφανά αρχεία στο cloud storage. | Λίστα cascade δεν τα περιλαμβάνει |
| A5 | Δικαιώματα | **Μέλος R&D (view-only) δεν μπορεί να δημιουργήσει ΚΑΜΙΑ εργασία** — ούτε «Κράτα το για μένα». Η παλέτα «Νέο» του δείχνει όλες τις προθέσεις και μετά 403 «Έργα & υλοποιήσεις → Επεξεργασία». Θέλει απόφαση: ή δικαίωμα «δική μου εργασία» χωρίς board.edit, ή να κρύβεται το «Νέο». | jmitrousis → Νέο → Κράτα το για μένα → 403 |
| A6 | Λογαριασμοί | Ο admin `admin` είναι ενεργός **χωρίς ομάδα** → με strict δικαιώματα δεν βλέπει τίποτα (ο `support` είναι σωστά χωρίς). | healthcheck / mod_cpm_team_members |

## Β — μπερδεύουν

| # | Πού | Τι |
|---|---|---|
| B1 | Καρτέλα εργασίας | Το «▶ Ξεκινάς τώρα;» (noClose) εμφανίζεται **κάθε φορά** που ανοίγεις δική σου εργασία χωρίς χρονόμετρο, ακόμη και για μια ματιά· και ξαναρωτά στο επόμενο άνοιγμα. Πρόταση: ρώτα μία φορά ανά εργασία/ημέρα, ή κάν' το λωρίδα (όχι modal). |
| B2 | Παλέτα «Νέο» | **Διπλό Enter = διπλή εργασία**: το `create()` δεν κλειδώνει όσο περιμένει το API. |
| B3 | Καρτέλα εργασίας | Για χρήστες χωρίς «Προσφορές» η καρτέλα καλεί `offers&client=` και τρώει 403 σιωπηλά (θόρυβος στο log, άσκοπη κλήση). Να καλείται μόνο με `cnpCan('clients.offers')`. |
| B4 | `move_task` | Άκυρη κατάσταση → `{"ok":false}` χωρίς μήνυμα· η οθόνη δεν λέει τίποτα. |
| B5 | `quick_task` | Τίτλος >200 χαρακτήρων κόβεται σιωπηλά (300→200). Να ενημερώνει ή να μεγαλώσει το όριο. |
| B6 | Πελάτης 360° | `#/client360` χωρίς id → **κενή οθόνη** (μόνο «Νέος πελάτης»). Θέλει επιλογέα πελάτη ή ανακατεύθυνση στη Λίστα πελατών. |
| B7 | Ειδοποιήσεις | 119 ειδοποιήσεις έχουν «????» στη βάση (4-byte emoji σε utf8mb3). Στο καμπανάκι/push διορθώνεται στην εμφάνιση, αλλά όποιος γράφει emoji σε τίτλο ειδοποίησης πρέπει να χρησιμοποιεί 3-byte (⚠ ✅ ❓) — να μπει κανόνας στον `pushNotification` (αντικατάσταση 4-byte με 3-byte). |
| B8 | Δεδομένα | 13 έργα πελάτη **χωρίς τμήμα** (παλιά, πριν γίνει υποχρεωτικό) και 9 ανοιχτές εργασίες **χωρίς ανάδοχο και χωρίς έργο** — τις βλέπει μόνο το τμήμα τους. Μία οθόνη «ορφανά» για καθάρισμα. |
| B9 | Δικαιώματα (healthcheck) | Οι δυνατότητες `reports.time` και `finance.billing_ok` δεν φυλάνε καμία ενέργεια (οι ενέργειές τους μεταφέρθηκαν σε row-level). Το κουτάκι στις Ομάδες λέει ψέματα — να αφαιρεθούν ή να ξαναδεθούν. |
