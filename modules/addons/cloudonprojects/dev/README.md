# Έλεγχος διάταξης καρτέλας εργασίας

Η διάταξη της καρτέλας (ζητούμενο / ενέργειες / δεξιά στήλη) έσπαγε επανειλημμένα με
«αθώες» αλλαγές CSS: πότε κρυβόταν το πεδίο γραφής, πότε το κείμενο έπιανε τον μισό
χώρο, πότε η μεγέθυνση άφηνε ορατό το ζητούμενο. Αυτός ο έλεγχος **μετράει** τη
διάταξη σε πραγματικό browser αντί να την εικάζει.

```bash
cd modules/addons/cloudonprojects/dev
PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers /opt/plesk/node/20/bin/node tk-check.js
```

Ελέγχει σε 1920×1080, 1440×900, 1280×800 — κανονικά και σε μεγέθυνση:

- το πεδίο «τι έκανες» είναι μέσα στην καρτέλα και έχει ύψος
- το κείμενο ενός βήματος πιάνει ≥85% της γραμμής
- οι ενέργειες παίρνουν ≥55% της στήλης και δείχνουν ≥2 βήματα χωρίς κύλιση
- τίποτα δεν ξεχειλίζει, η σελίδα δεν κυλά
- κανονικά: η δεξιά στήλη ορατή και ακέραιη, οι ενέργειες δεν την καλύπτουν
- σε μεγέθυνση: κρύβονται δεξιά στήλη ΚΑΙ ζητούμενο, οι ενέργειες πιάνουν όλο το πλάτος

Το `tk.html` φορτώνει το ΠΡΑΓΜΑΤΙΚΟ `projectmanagement/app.css`, οπότε κάθε αλλαγή στο
CSS ελέγχεται αμέσως. Τρέξ' το πριν και μετά από κάθε αλλαγή στη διάταξη.

# Γενικός έλεγχος συστήματος — `sweep.sh`

```bash
bash modules/addons/cloudonprojects/dev/sweep.sh
```

Δεν ψάχνει «θεωρητικά» λάθη· ψάχνει τις **κατηγορίες** λαθών που μας έχουν χτυπήσει
στην πράξη. Κάθε ενότητα γεννήθηκε από πραγματικό περιστατικό:

| # | Τι ελέγχει | Το περιστατικό |
|---|---|---|
| 1-2 | σύνταξη PHP / JS | τυπογραφικό πήγε live για 1΄ και έβγαλε parse errors |
| 3 | `window.CNP.x` που χρησιμοποιείται χωρίς να ορίζεται | το κουμπί αναζήτησης ήταν νεκρό (`palette`) |
| 3β | ονόματα που αποδομούνται από το `window.CNP` | ένα λάθος όνομα γίνεται σιωπηλά `undefined` |
| 3γ-3δ | συναρτήσεις/στατικές μέθοδοι που καλούνται χωρίς να υπάρχουν | `cnp_action_area()` — σκάει μόνο στον χρήστη |
| 4 | `mb_substr` σε πεδία περιεχομένου | οι «Ενέργειες» κόβονταν στους 200 χαρακτήρες |
| 5 | `api('x')` χωρίς endpoint· endpoint εκτός μοντέλου δικαιωμάτων | το `event_rsvp_public` έκοβε με 403 κάθε RSVP πελάτη |
| 6 | πίνακες/στήλες που ζητά ο κώδικας | |
| 6β | ορφανές εγγραφές & ακεραιότητα ιεράρχησης | |
| 7 | fatal/parse errors στο σημερινό log | |
| 8 | αν τα cron μπορούν να γράψουν το log τους | 7 εβδομάδες νεκρά pulse/daily: η ανακατεύθυνση `>> log` αποτύγχανε και το cron ΔΕΝ έτρεχε καθόλου την εντολή |

Τα βοηθητικά `*.php` του φακέλου τρέχουν **μόνο από γραμμή εντολών** (CLI guard +
`.htaccess`).
